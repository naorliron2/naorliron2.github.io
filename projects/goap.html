GOAP

Goal Oriented Action Planning AI.

  • AI
  • Unity
  • Reusable system

“Goal Oriented Action Planning (aka GOAP, rhymes with soap) refers to a STRIPS-like planning architecture specifically designed for real-time control of autonomous character behavior in games.” — Jeff Orkin

From FSM to GOAP

First used in 2005 in the game F.E.A.R., GOAP uses a set of actions, kind of like a finite state machine, but by disconnecting these actions, scaling up systems becomes much easier. So this becomes this.

Actions can be connected by the planner, which makes adding new actions a lot easier.

As you can see here, each AI agent has an overall goal and a current state (usually referred to as the world state), and the planner can switch actions based on the world state.

Actions

Each enemy holds a set of possible actions it can do.

Each action has its data, and the data holds 3 things: the preconditions (what the world state needs to be in order to do the action), the effects this action has on the world state, and the cost of the action (if two actions have the same effect, the action with the lower cost will be done).

The planner

The planner script is responsible for checking what actions are currently available and whether they achieve the goal we need.

Once the planner has found a path, it queues up the actions, and that's pretty much it. This example is pretty small-scale and a finite state machine would have worked just as well, but now these scripts can be dropped into any project and adapted to its needs.
