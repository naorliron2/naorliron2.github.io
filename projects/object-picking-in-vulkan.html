Object Picking In Vulkan

A short tutorial about object picking in Vulkan.

  • Vulkan
  • C++
  • Tutorial

I'm working on a Vulkan render engine and I wanted to be able to click on objects in the scene to select them. As a programmer, the first thing I did was a quick Google search, and I was a bit disappointed with the amount of material I found, so after managing to implement it myself I decided to write a blog post about it.

Quick disclaimer: this is by no means the best way to implement object picking, but I will show what worked for me.

The theory

What we're trying to do here is give every object an ID. You can pass it either through descriptors or vertex attributes (I chose the latter; for bigger projects I would recommend using descriptor sets), and then write that ID into an SSBO in the fragment shader.

Attachments

Cool! Let's start implementing. We'll start by creating the color and depth attachments for the framebuffer. The ID is a uint32_t, so we have a max of 4,294,967,295 objects. You'll notice that our color attachment is VK_FORMAT_R32_FLOAT; for some reason when the texture is UINT instead, I get garbage values, so I stuck with that, since it is for debug purposes anyway.

Framebuffer and render pass

Now VkFramebuffer creation. Notice that there is a separate render pass for object picking.

The pipeline

And a separate VkPipeline. Most of this VkPipeline is pretty standard, but a few things are important to mention.

First, we're going to have a VkDynamicState for the scissor. On every click we set the scissor to a size of (1,1) and an offset of (mouse_position.x, mouse_position.y). This is an easy optimisation: we can write the IDs in the fragment shader, knowing it only runs once.

Second, you need to bind an SSBO (Shader Storage Buffer Object) to the descriptor set of every VkPipeline you want to access the ID from, for read and/or write (meaning we definitely need it in the object picking VkPipeline).

Recording

To make sure I execute the object picking render pass only when the mouse is clicked, I set an internal flag before rendering that gets reset when rendering ends.

Reading the result

Now that the SSBO has the value of the chosen object, I can either read it on the CPU if it's host-visible (which is slower) or just read the SSBO in whatever shader stage I want.

Possible improvements

There are a few optimizations I didn't need but could be implemented.

The color attachment is only useful for debugging, as shown below, and could be removed as soon as you see everything is working as intended.

You could also use multiple render targets, meaning the whole object picking could be done in one render pass and one draw call.
